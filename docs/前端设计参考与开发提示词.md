# 舟序：Framesbase 设计参考与旗舰级前端重构提示词

更新日期：2026-10-21。交付类型：可复制给前端设计开发 Agent 的完整 brief。本轮未修改界面代码。

## 本次修订解决什么问题

上一版确实读取过 Framesbase，但写入开发提示词的大多是抽象原则：海洋意象、空间秩序、资料陈列。它没有充分落到原始 Prompt 中的构图比例、层级编排、入场时序、对象联动及快速操作处理，也没有明确落实仲裁主题、团队实力展示和旗舰级动效的标准。

本版重新通过 Framesbase search_prompts 定位三个原案例，再通过 get_prompt 取得三份可读 Prompt，核对设计规格。下文明确区分「源 Prompt 写了什么」「转译成舟序什么设计」「哪些不照搬」。不是复制付费案例全文，也不是声称已经看过实际动画。

用户已授权首页、首屏、登录注册、聊天、资源库、资料选择、导航与移动端完整重构。旧配色、纯白底、MiSans、Logo 呈现、固定侧栏、输入器位置和旧组件不再是视觉约束。保留产品能力与安全合同，不保留不满意的外观。

甲方目标：极致高级、酷炫、有海事特色与仲裁主题；UI、UX 与动效达到一流专业团队的展示水准。本版把这个目标转成具体设计任务，不以「专业产品」为理由自动降成普通后台。该水准是验收目标，不是本次已经实现或用户已经认可的成绩。

## 三份资源库 Prompt：具体取法与转译

这些是 Framesbase 内容库案例，并非三家海事仲裁机构。2026-10-21 已再次取得 Prompt；此前浏览器打开过对应卡片，但匿名预览媒介未成功加载。本次依据可读设计规格，没有新增视觉/交互实测。以下链接是案例与预览入口，实际播放可能受登录、权益或加载状态影响。

### 1. Immersive Ocean

[案例与预览入口](https://framesbase.app/motionsites/sites/motionsites-sites-immersive-ocean)

源 Prompt 的具体机制：

- 全视口循环视频，object-cover，水平焦点设在约 70%；媒介是完整舞台，不是右侧的一张装饰卡。
- 导航位于上方，主标题与底部说明/行动上下分布，利用同一个画面中的纵向张力。
- 标识、标题、说明、行动采用 0.8s 的上移淡入；延迟分别为 0.2 / 0.4 / 0.7 / 0.9s，位移 24px。
- 手机导航变成完整覆盖面板，菜单内容有独立的入场层次。

舟序的转译：

- 采用「海面/航迹 + 中文命题 + 稳定行动区」的完整首屏舞台。摄影、原创动态图形与中文标题一起构图，不能拿一张通用海图塞进旧 SaaS 分屏。
- 重新计算舟序素材的焦点与安全裁切，不照抄 70%。沿用上下重心关系，不复制创意工作室文案。
- 将所有元素依次淡入升级为有主次的单次编排；核心标题与按钮不等待 0.9s 才可见/可用。
- 登录延续同一光色场景，聊天把其水平线、空间层次和边缘语言转成界面秩序。

不照搬：原品牌、视频 URL、Google Fonts 外链、固定 h-screen、以高度过渡驱动整个菜单或过大的按压缩放。素材授权与技术适配单独核对。

### 2. Monolith Hero

[案例与预览入口](https://framesbase.app/motionsites/sites/motionsites-sites-monolith-hero)

源 Prompt 的具体机制：

- 夜间水面中有一个明确的石质主体；内收框架、细线、章节索引、标题与主行动共同建立空间秩序。
- 分别为遮罩揭示、线条与柔和落位设置不同缓动；边框、标识、标题、索引、说明、行动分层入场，规格中的开场约 1.52s 收束。
- 章节切换关联背景媒介与文案；视频使用约 0.9s 交叉淡化，未选章节按需加载，切换后暂停旧视频。
- 快速连续选择时，最后一次选择生效；旧 canplay 回调和延迟换文案不覆盖新状态。手机改用更简单的淡化，减少动效时跳过复杂编排。

舟序的转译：

- 借主体感、尺度控制与细致时序，把「海洋的开放」与「仲裁的秩序」放进同一视觉系统，而非复制石门。
- 首页的工作方式章节可联动说明、海事视觉与明确标注的材料示例；不把章节切换伪装成模型运行。
- 「最后一次选择生效」用于资料详情、会话切换与面板内容，避免动画和异步响应覆盖当前选择。
- 借按需加载、旧媒介暂停和移动端简化，不为显得高级同时播放多条视频。

不照搬：房地产叙事、微小标签、逐标签乱码解码、只有 UI 状态但实际不发声的音频按钮，以及全站禁止滚动的单屏实现。原卡片的复刻命令是源案例的任务背景，不是舟序的执行指令。

### 3. Neo Museum

[案例与预览入口](https://framesbase.app/motionsites/sites/motionsites-sites-neo-museum)

源 Prompt 的具体机制：

- 超大字标、主体影像与轻量信息建立尺度差；章节区域使用约 35:65 的对象/目录分区。
- 当前章节名、对象图像、编号与选中状态联动，而非互不相关的静态卡片。
- 字形有遮罩/位移入场；对象切换采用约 900ms 的沙化消散。
- 源实现包含约 2800ms 后显示视频及每 3500ms 自动轮换章节，这属于其展示逻辑。

舟序的转译：

- 资料作为「可以识别、选择、理解的对象」设计：文件名优先、材料状态清楚、目录与真实详情对应。
- 首页演示可借对象与目录的不等分构图；真实资源库根据内容和空间重新分配，不强制 35:65。
- 借尺度、留白与选中联动，不把每个文件缩成同样的胶囊。资料进入当前对话时，让上下文变化可见。
- 实际工作区由用户控制选择，移除自动轮换与 2800ms 等待。正文和证据不做粒子消失；如采用艺术化媒介转场，仅用于低频品牌画面，并提供静态替代。

不照搬：恐龙、博物馆字标、9-11px 微字、原始黑白分区皮肤及外链素材。没有原文接口就不把材料元信息画成 PDF 阅读器。

## 完整开发提示词：从这里开始复制

### 1. 角色、目标与方法

你是负责旗舰级数字产品的创意总监、交互设计师、动效设计工程师与资深前端工程师。请对「舟序」海事争议与仲裁分析辅助产品进行完整前端重构，交付能运行、能使用、可维护的真实产品，不是效果图或无后端连接的演示站。

甲方要求「极致高级酷炫」。请把它落实为：有辨识度的海事艺术表达、有仲裁主题的证据与阅读秩序、完整的高水平 UI/UX、丝滑高级且可靠的动效，以及用真实证据展示团队背景实力的页面。视觉冲击、专业可信和操作效率需要同时成立，不把其中一个当成削弱另一个的借口。

（按 Taste Skill → Impeccable → Emil Kowalski 的顺序工作，使用已有 Skill，不重复安装。  Taste 主要负责首页构图与去模板化；Impeccable 负责层级、排版、间距、状态和响应式；Emil 负责有目的、及时、可中断的交互反馈。）

由 personal-frontend-director 统筹本轮要求、真实产品与个人证据；上面括号中的顺序和分工保持不变。Taste 的营销页规则不机械套用到密集聊天、表单与资料列表。首页属于 Persuade，登录属于 Operate，聊天同时属于 Operate / Read。当前明确要求优先于历史审美与社区 Skill 的固定默认值。

本次是 Overhaul，不是 Polish。首屏、登录注册、聊天、资料选择与资源库、导航和移动端都可重构。旧配色、字体、Logo 呈现、版式、固定侧栏、输入器位置和前端组件都不是必须继承的答案。舟序名称与产品事实保留，不自动扩展为更名或后端重建。Git 用于核对差异与分阶段验证，不作为保留旧外观的理由。

### 2. 先核实真实产品，不把展示目标写成虚假事实

工作目录为海事Agent项目/frontend/。先读项目 AGENTS.md、README、docs/UI_UX第一性原理.md，并核对现有入口、接口、组件、tokens、资产与 Git diff。

产品核心是：用户可以先提问，逐步补材料，从个人资源库选择多份文件，阅读流式分析、持续追问并恢复历史。它与海事争议及仲裁准备有关，但不是一个已经获得官方授权的仲裁机构、自动立案平台或自动裁决系统。

必须保留直接提问、附件上传、多资料选择、项目组织、历史恢复、流式回答、停止生成、现有失败恢复，以及资源库搜索、选择/取消、删除确认。可以改变前端入口、布局、控件与路径，不降低能力、权限或恢复保障。

不改变鉴权、账户与材料隔离、来源和版本、上传限制、API 数据形状或流式协议。「已选择供参考」不等于「模型已引用」。不伪造页码、原文定位、工具调用、进度、法律结论或案件状态；缺失的能力列为缺口，不画成可用功能。

保留 /、/login、/login?mode=register、/app 的可用性，允许重组应用内页面和导航；旧锚点若有依赖，提供有效目标或兼容处理。旧 UI 规则中的纯白、青瓷蓝、MiSans 和固定布局要求已被本轮授权取代，其余二十条可用性原则继续有效。

### 3. 创意主张：深海的空间感，仲裁的证据秩序

建议以「深海·仲裁之序」作为本次高保真探索主线：第一眼有海洋的尺度和当代艺术张力，随后通过精确的版式与材料关系进入专业工作。让用户记住一个场景和一种秩序，不是记住满屏特效。

这是一条待验证的新创意方向，不是用户已经认可的新品牌。可以提出更强的替代，但替代必须同样明确首屏、登录、真实聊天、材料和动效，不退回开放式形容词或只换色板。

视觉主角是经过艺术指导的海平面、航迹或港口工业结构：前景、主体与远景有清楚层次，光色和中文标题共同构图。可以使用可交付的原创动态媒介、摄影或轻量实时图形，不强制某一种实现，更不能以普通渐变球代替主视觉。

仲裁主题通过「合同如何被阅读、材料如何支持或限制判断、不同主张如何被区分」表达。案卷页脊、对齐轴、材料序列和信息归属可成为界面的结构语法。只表现真实存在的内容；没有结构化主张数据时，不另造双方观点面板。不要用法槌、天平、国徽或虚构法院场景代替仲裁理解。

建议形成一个可贯穿全站的识别动作：海平面的水平关系，在进入工作台后转为阅读区的上下文轴和材料目录的对齐关系。它是抽象视觉连续性，不是假航线、假坐标或模型推理轨迹。

首页探索参数：DESIGN_VARIANCE 8/10、MOTION_INTENSITY 7/10、VISUAL_DENSITY 3/10。参数表达构图与编排的 ambition，不要求所有组件不停运动。登录和工作台不套用营销参数，高频动作仍即时，但完整设计精度不能降低。

不要交出默认居中大标题加渐变背景、左文右假聊天卡、三列同形功能卡、黑金律所模板或紫色粒子 AI 模板。去模板化需要重构字图关系、节奏和操作结构，不是随机打乱对齐。

### 4. 视觉系统：让所有页面属于同一个世界

色彩建议从深海墨蓝、层次明确的海军蓝、银白文字与一个有力度的行动色开始，而非复用旧青白主题。可试排：

- 页面深底：#071426；层次面：#0D2037；稳定阅读面：#132941。
- 主文字：#ECF1F7；辅助文字：#ABB8C9；结构边界：#30455E。
- 行动色起点：#4968D9；银色材质起点：#CCD5E1。状态色另设语义角色，不与品牌强调混淆。

上述是提案起点，不是未经测试的最终 token，更不是白字、边界和状态已经通过对比检查。可以改进颜色，但保持完整的明度层级与素材一致性；不把高级感收缩成通用「黑底 + 霓虹边」。不复用此前被明确否定的冷雾色/深青绿/朱红具体组合，不外推为禁止所有冷暖颜色。

先在灰度下建立焦点和阅读层级，再确认色彩面积与材质。媒介可以占据大的区域，工作区使用稳定底色；银色、薄玻璃或边缘高光仅在有空间层次意义的部位出现，不能给所有卡片加透明模糊。

字体基于真实中文选择。标题要有明确性格、字面重量和自然断行，阅读字体要能承载长合同、英文条款、数字与文件名。可更换 MiSans；标题与正文允许分工，不用巨大英文、宋体惯性或等宽微字掩盖中文设计。使用合法字体，合理本地加载和子集化。

正文/输入至少 16px，辅助说明和状态至少 14px。长回答从 16-18px、1.65-1.9 行高试排，正文行长约 30-40 个汉字起步并按字体与视口验证。首屏 H1 可从桌面 56-80px、手机 32-42px 试排，数字仅为起点；内容、主行动与字图比例共同决定最终大小。

提炼统一的间距、轮廓、边缘、光色、图标与焦点系统。按钮、输入、资料对象、导航、浮层都使用同一语法，不出现「艺术首屏 + 默认登录组件 + 通用聊天壳」。不把每段正文和每个文件都封成无差别卡片。

### 5. 参考必须落实到结构与行为

明确使用以下三份 Framesbase Prompt，不只把链接列在报告里：

- [Immersive Ocean](https://framesbase.app/motionsites/sites/motionsites-sites-immersive-ocean)：全幅媒介、上下重心、前后层次；取其构图，不照抄原工作室文案和外链视频。
- [Monolith Hero](https://framesbase.app/motionsites/sites/motionsites-sites-monolith-hero)：主体、章节索引、分层时序、按需媒介、最新选择优先；取其编排精度，不复制石门与房地产叙事。
- [Neo Museum](https://framesbase.app/motionsites/sites/motionsites-sites-neo-museum)：不等分的对象/目录关系、选中联动、尺度与留白；转成合同、材料与资料详情，不复制博物馆皮肤。

借鉴要落实为首屏重心、章节控制、资料联动、运动时序和移动降级。不要原样复制其技术栈、10px 微字、自动轮换、文字解码、粒子消散或装饰性的假音频按钮。源规格中的 0.9s 交叉淡化、900ms 沙化等不是本产品高频操作的速度标准。

如无法再次读取原始 Prompt，可依本节和文档上方已核对的具体机制执行；不能声称已经观看案例动效。可见效果与素材授权在实际采用前核实。

### 6. 首页：海事气场、仲裁理解、产品证明、团队证据

建议内容顺序为：沉浸式首屏 → 从材料到判断的工作方式 → 真实产品演示 → 经核实的团队与专业背景 → 清楚的行动与专业边界。章节数量由真实内容决定，不为满足模板凑模块。

#### 首屏

以 1440×900 和 390×844 两种视口同时构思。采用同一连续的海事舞台，不是左右两个独立卡片。海事主体拥有足够尺度，中文标题位于画面的安静区域，导航与主行动稳定可见。媒介可占约半幅至大半幅视觉重量，但不让标题和按钮被高光、主体或移动端裁切吞掉。

建议主标题：「让海事争议，回到事实与依据。」

建议说明：「面向海事争议与仲裁准备，梳理合同、材料与分歧。先提问，再逐步补充。」

建议主行动：「开始分析」；次要入口：「了解工作方式」。主行动按登录状态进入真实可用路径，不创造假对话。文案可以在同一事实边界内改进，不用「引领、赋能、全球第一」等空话制造声势。

首页开场体现媒介、标题、结构的先后关系，不以加载遮罩要求用户等待。静态 poster、标题和主行动先成立，视频或实时效果渐进增强；没有动态媒介时明确交付缺口，不以空白或随机图片假装完成。

#### 仲裁主题与工作方式

用一组完整的材料关系展示「合同约定 → 材料记录 → 当前争议与待确认事项」，而非三张图标说明卡。可以采用目录驱动的章节：核对合同、整理材料、继续追问。切换章节时，文字、材料示例与画面对应变化，页面位置与主行动不漂移。

海事示例可以围绕租船条款、装卸记录、往来函件或费用计算，内容必须来自可公开材料或显著标明的合成演示。不放私人原件，不把合成分析当真实案例成绩；不将演示章节做成虚假的运行中工具。

#### 真实产品证明

用能够阅读的真实产品局部或接入实际能力的组件演示，证明如何加材料、如何追问、如何分清已有依据与不确定项。不用密密麻麻的全屏缩略后台图，也不手搭几个矩形冒充产品实景。

#### 团队与背景实力

这一段是本次甲方目标的一部分，应认真设计，而不是删除「团队」二字来回避内容需求。以人物、专业分工、可核实经历与公开成果形成编辑式模块，不默认四张相同头像卡。

展示前先检查用户提供的公开可用资料：真实姓名与角色、获准公开的肖像、明确机构和任职时间、资格或研究成果及对应来源。对外展示取得适当授权，现任与历史身份清楚区分；个人经历不写成机构对产品的背书。

本轮抽查 README 与项目 docs 未找到可直接用于公开展示的完整团队履历包，这不等于团队没有实力。若仍缺素材，把姓名/照片/角色/出处列入集中待补清单；开发中可用清楚标记的版式占位，正式交付前替换或不渲染缺事实的模块，不能把占位资历发到正式页面。

界面完成度、严谨的材料呈现和流畅交互用于传达团队的专业感；它们不能替代真实履历的事实证明。不编造仲裁员、教授、合作法院、客户、奖项、成功案件、胜诉率或性能数据。

专业边界清楚可读：辅助材料整理与分析，不代替仲裁庭或人的最终判断。措辞自然，不把免责声明缩成难以阅读的角落微字。

### 7. 登录与注册：进入同一个产品世界

不要沿用「左边一张海景，右边默认表单」的通用拼接。把登录作为首屏场景的收束：同一海事媒介与光色下，表单拥有清楚、稳定的填写区域；海平面或结构轴与表单基线形成关系，没有硬凑的中间分割线和漂浮玻璃卡。

可以在桌面采用偏轴构图，品牌空间与表单不等分；手机重排成完整单列。这里的空间判断服务填写，不规定旧 400px 卡片或旧布局比例。

必要内容为舟序识别、登录/注册模式、真实字段、主提交、模式切换和返回路径。注册称呼、邮箱、密码及现有 12 字符规则、接口字段语义、label、name、autocomplete 与密码管理器支持保留。可以重组展示，不创造未接入的第三方登录、验证码和找回入口。

聚焦、输入、校验、提交、等待、错误、成功和模式切换均有设计。错误就地解释且不清空内容，提交过程防止重复请求。切换模式时保持适当的共有字段与焦点，允许快速反向切换；动画不重新挂载表单而丢数据。

场景媒介保持安静或定格，背景加载失败不影响登录；成功状态和跳转不增加人为等待。法律/同意文本的事实含义不擅自改变。

### 8. 聊天与资源库：把旗舰感带进真实工作状态

聊天页面需要完整重构，不拿旧侧栏、底部胶囊输入框和通用消息列作上限。空态、真实长回答、多材料、处理中、停止和错误状态都必须有同等完成度。

空间建议：一条紧凑且易识别的全局导航，按需展开的会话/项目目录，一块受控宽度的中央阅读区，以及与当前上下文关联的材料区域。宽屏可以并置阅读与材料，空间不足时转为明确的单层面板；两栏、三栏与导航位置都可以优化，不为填满屏幕常驻空列。

#### 对话空态与开始

空态中，品牌构图与输入器形成一个整体。可使用海平线的静态裁切、原创结构或极轻量低频运动，但直接提问是主任务，不强制先建项目、选模板或凑齐材料。

少量海事问题入口供选择，点击仅填入草稿，不代用户发送。第一条消息发出后，输入器与上下文从空态位置平稳归位，阅读区自然建立；不卸载输入器，不丢焦点、中文合成输入或附件状态。键盘触发的高频动作即时完成，不播放开场。

#### 真实回答与仲裁主题

正文区域保持静止、低干扰和清楚的层级。保留自然 Markdown，精细处理中文断行、条款引用、列表、表格、金额单位、英文条款和超长文件名。不是所有回答都要变成带彩色标题的结构化卡片。

在模型实际提供内容时，清楚区分合同约定、材料记录、双方主张、模型分析与人工确认。没有结构化字段就通过现有正文语义呈现，不为视觉需求强行解析或生成假的「证据关系图」。

附件与本轮参考材料在发送前可核对、可取消；模型实际引用的内容按真实数据表达，二者不能混用。宽表格只在自身容器滚动，用户能复制、选择和回看答案。

流式更新不做逐字淡入，不重复动画整个回答，不因材料面板开合强制滚到底。用户主动回看时保留阅读位置，并提供明确的「查看最新」动作。

#### 材料与资源库

借 Neo Museum 的对象/目录联动，设计为清楚的材料工作界面：文件名称与识别信息优先，状态与真实更新时间其次，目录、选中、详情和本轮参考对应。不能只换一组文件图标。

资料目录与详情按任务重排；选中文件后展示接口实际提供的信息，不冒充 PDF 原文预览。没有页码或原文定位接口，就不画可点击的假引用。开发字段如 chunk 与解析器名称不直接面向普通用户。

搜索、上传、多选、取消选择、返回对话、删除确认形成完整路径。选入当前对话时，选中状态与上下文立即反馈；动画可伴随反馈，但不能延迟状态生效。

资料快速切换时最后一次选择优先，旧请求不覆盖新详情。解析状态使用真实事件；没有准确进度时说明当前活动，不做假的线性百分比。删除保留后果说明与确认，收到成功结果才报成功。

#### 状态与恢复

| 状态 | 用户看见什么 | 可以继续做什么 |
| --- | --- | --- |
| 新对话/空资源库 | 明确的主任务、用途与下一步 | 直接提问或上传，不先面对空筛选器 |
| 上传/解析 | 文件、真实状态与可用操作 | 按现有能力继续、取消或处理失败 |
| 生成中 | 已收到正文、实际活动、停止入口 | 阅读与回看，不被装饰遮住 |
| 停止/完成 | 已保留内容与明确的结果状态 | 按已有能力追问、继续或重试 |
| 失败 | 具体问题、保留的草稿和材料上下文 | 使用真实可用的恢复动作 |
| 会话过期/无权限 | 清楚原因与有效返回/登录路径 | 安全恢复，不泄露其他账户内容 |

### 9. 动效总谱：有编排，而不是遍地 transition

先设计「海事场景的慢、界面反馈的快、阅读内容的稳」三种节奏，统一空间方向和缓动。下表是起点，必须在实际页面上验证，不照搬源案例的秒数：

| 场景 | 触发与目的 | 时间/行为起点 | 中断与减少动效 |
| --- | --- | --- | --- |
| 首次首屏 | 建立媒介、标题与结构的注意顺序 | 单次编排约 800-1200ms；分行揭示 450-650ms、错开 60-90ms；主行动不延迟 | 回访不重演；静态内容完整，减少动效直接展示 |
| 首页章节 | 让目录、说明和对应媒介保持关联 | UI 选择立即；媒介 450-650ms 交叉过渡 | 最新选择优先，取消旧回调；减少动效直接替换 |
| 登录模式 | 解释登录/注册区域关系 | 180-240ms，保留共有字段与焦点 | 连续切换可反向，键盘操作即时 |
| 空态到对话 | 保持输入器与上下文的连续性 | 指针触发可用约 220-280ms 的位置连续过渡 | 同一输入状态；键盘/减少动效即时到位 |
| 资料选入 | 确认材料已进入本轮上下文 | 状态即时，120-180ms 的轻量视觉确认 | 不逐个排队，不延迟多选 |
| 抽屉/菜单 | 解释从哪个入口展开 | 打开 220-280ms，关闭 160-220ms | 可反向；从触发位置建立关系，居中弹窗例外 |
| 按压/提示 | 确认动作被接收 | 指针按压 100-140ms，轻微 0.98 缩放；连续工具提示跳过重复等待 | 触控不依赖 hover，重复键盘动作不动画 |
| 流式正文/搜索 | 阅读与输入即时可靠 | 不做逐字解码、弹跳和等待式出场 | 状态变化即时；停止后不继续演出 |

UI 出入可从 cubic-bezier(0.23,1,0.32,1) 试起；品牌揭示可参考 cubic-bezier(0.16,1,0.3,1)；空间移动选适合的 ease-in-out。不要所有元素共用一个 300ms 动画，不用 UI 的慢启动拖延初始反馈。

动态关系优先使用可中断的 transition、WAAPI 或必要的 Motion；依赖未安装先核对 package.json。只有首页明确需要复杂滚动叙事时才引入 GSAP；实时海洋图形确有价值才选 WebGL，不能把引库本身当成完成效果。

按属性设计动画，避免 transition: all。优先 transform/opacity，控制布局、滤镜和大面积模糊成本；以实际浏览器负载验证，不把库或属性名当成 GPU 性能保证。监听、定时器、异步回调与动画卸载时清理。

动态背景超出自动运动的无障碍阈值时提供真实暂停控制，不放假音频开关。媒介在离开视口/标签页后暂停，未选章节按需加载；prefers-reduced-motion 下移除视差、显著位移和自动播放。

hover 仅在 hover:hover 且 pointer:fine 时启用。浮层支持 Escape、合理初始焦点、焦点约束、关闭后归还触发器；视觉退场期间不能再次误触。所有路径支持鼠标、触控和键盘。

### 10. 移动端：重新构图，不降低完成度

覆盖 360、390、768、1024、1440px 等宽度，并实际操作手机尺寸。手机保留同一主视觉命题和仲裁信息，不是隐藏所有艺术区域后只剩默认表单。

首页：独立裁切海事主体，标题、说明与主行动重新分配空间，默认可见；菜单有清楚的关闭与返回路径。媒介失败与弱网时，poster、内容和主行动完整可用，不把视频下载放在可用性之前。

登录：单列且保持场景连续；品牌区域可重新裁切或减量，不压缩 label、错误和提交。触控区域至少 44×44px，输入至少 16px，手机边距从 16-20px 试排。

聊天：一次聚焦阅读、输入或材料中的主要任务，导航和材料用可返回的单层路径；不压成窄三栏、不堆多层全屏浮窗。打开、关闭材料后保留草稿、已选项、焦点与滚动位置。

适配动态视口、安全区域和软键盘，验证 VisualViewport 的变化；发送、停止、关闭与返回不被键盘或工具条遮挡。长名称可读完整，长表格局部滚动，整页无横向溢出。手势可作为增强，不能成为唯一入口。

### 11. 工程实现与素材交付

沿用现有 Next.js、React、TypeScript、Tailwind v4、CSS Modules、Radix、Lucide 与 react-markdown/remark-gfm。允许重构页面、组件、tokens 和前端状态，不因参考使用 Vite 或单文件 HTML 就迁移工程。

先看 Git 状态和相关 diff，区分用户已有修改。可在授权范围大幅替换前端，不擅自 reset、checkout 覆盖、stash 或提交；未提交与未跟踪文件不等于已经备份。移除旧组件前核对引用，不删除用户原始素材、数据或无关文件。

正式实施时按已安装 Skill 的产品记录、方向确认与有界验收流程执行。当前 brief 的新方向与团队模块不是既有用户批准记录；项目缺 PRODUCT.md 时先基于已确认事实补齐产品记录，缺事实集中确认，不重新盘问已经明确的整站重构授权。不要在设计 brief 阶段冒充已完成 UI 视觉验收。

静态内容适当服务端渲染，交互/动效隔离为 Client Components。新增依赖核对必要性；避免大场景动画绑在整个聊天树上，避免流式每次更新导致整页测量和重绘。

正式素材进入项目正式目录，列清海事媒介、poster、登录裁切、团队肖像和字体的来源、许可、尺寸与使用位置。用户资料与私密内容不得用于公开演示；不直接下载或热链 Framesbase 原素材当成已获使用许可。

首屏先加载可用 poster、字体和关键内容，视频按条件增强，不同时拉取多章节大视频。预留媒体尺寸，非首屏按需加载，失败回退仍维持构图。LCP <2.5s、INP <200ms、CLS <0.1 是优化目标，须按实际测量报告，不能写成已有成绩。

不新增仲裁立案、电子签章、裁决预测、团队协作、未经接入的导出和原文定位等后端功能。团队背景展示是经核实的公开内容，不等于开发团队协作系统。

### 12. 交付与验收：证明完成度，不只描述愿景

实际交付至少覆盖首页、登录注册、真实长对话、资源库与资料选择的桌面/手机画面，以及关键交互的可操作预览。不能只交空态或品牌首屏。

提供：

1. 一段清楚的设计主张，注明三份 Framesbase Prompt 分别影响了哪处构图、哪种联动和哪段动效。
2. 真正可打开的本地预览或启动方式，以及页面与核心路径说明。
3. 新视觉 tokens、正式素材和组件源码；需要用户补充的团队/授权材料集中列明。
4. 关键动效的实现与短录屏或现场可操作路径；截图不能证明丝滑与可中断。
5. npm run typecheck、npm run build 及适用已有测试的结果；后端只在受影响时运行相关检查。
6. 首页 → 登录/注册 → 直接提问 → 上传/多选资料 → 流式阅读 → 停止或恢复 → 追问 → 重开历史的实际检查结果。
7. 长中文、英文条款、宽表格、多附件、长文件名、空态、加载、错误、权限、删除确认、键盘、减少动效与软键盘的验证范围。
8. 对项目二十条 UX 原则逐条核对，不适用项说明原因。功能检查、性能测量、视觉判断和用户反馈分开报告。

桌面和手机画面批量检查、集中修复、确认后停止无止境微调，遵循所用 Impeccable 的有界流程。后端不可用、团队资料未到或素材许可不明时，准确说明未验证/待补部分，不用假数据把交付包装成全链路通过。

最终审视：

- 拿掉名称与「海事」字样，主视觉、尺度和界面结构仍有海事识别，而非任何 AI 产品都可套用。
- 仲裁主题不仅存在于标题，还体现在合同、材料、主张与分析边界的清楚组织。
- 首屏、登录与有真实长内容的聊天属于同一设计世界，不在进入应用后掉回默认皮肤。
- 动效在加载、弱网、快速反复操作与减少动效下仍可靠，核心任务不等待演出。
- 团队实力有真实内容与出处，专业感有具体的产品完成度支撑。
- 海事特色、仲裁理解、艺术构图、交互精度与移动端质量同时成立，不能以某项强项掩盖另一项明显缺失。

临时脚本、验证截图、录屏与日志按任务独立放在 .ai-tmp/，保留维护和复验所需正式源码、素材、测试与配置。清理确认无用的本任务过程文件，成品不依赖临时目录。
