## 5. 执行工具与隔离边界

### 工具职责

| 工具 | 职责 |
| --- | --- |
| `read` | 读取本任务工作区文本或列目录，返回文件哈希 |
| `write` | 创建文本文件；覆盖已有文件需提供当前哈希 |
| `edit` | 用当前哈希保护唯一匹配的精确替换 |
| `bash` | 在隔离环境中运行命令与 Python 脚本 |
| `present` | 将实际文件保存为交付快照，由前端提供下载入口 |

材料解析文本由服务端按可信运行范围导入；索引包含材料标识、解析状态、文本哈希和解析定位信息。大材料不能通过静默截断冒充完整导入，仍需通过材料工具继续读取。

### 当前已验证的执行配置

- 独立 Linux 容器，无宿主目录绑定挂载，无网络。
- 非 root 用户，只读根文件系统，移除 Linux capabilities，禁止获得新权限。
- 每个执行世界限制为 1 CPU、512 MiB 内存、64 个 PID。
- 工作区 64 MiB，临时区 32 MiB；单命令超时 30 秒。
- stdout、stderr 分别最多保留 64 KiB；服务内最多 4 个活跃执行世界。
- 执行环境不可用时明确失败，不回退宿主终端。
- 任务终结或取消后销毁容器及其派生进程。
- 相同脚本错误重复发生时提示读取脚本和数据；达到五次则停止该轮执行。

该边界是容器与进程隔离，不是针对所有共享内核漏洞的安全认证。未交付的临时脚本不保证在服务重启后恢复；已保存的交付快照与临时容器分开持久化。

## 6. 文件交付与访问控制

文件通过 `present` 保存实际字节及 SHA256，不由模型自行拼接下载地址。下载和预览接口都核对登录账户、运行与会话归属；预览转换在无网络、无宿主挂载的同一执行镜像内完成。

已验证本账户能够下载、另一账户返回 404、匿名请求返回 401，下载字节哈希与保存快照一致。修改容器内原文件不会改变已保存快照。

当前限制：单文件不超过 10 MiB；每轮最多 10 份文件、合计 30 MiB。Office 文件接受有限结构检查，包括必要 XML、根元素、ZIP 展开限额及活动二进制部件检查。该检查不是完整 Office 格式验证，也不证明文档没有外链、公式风险或专业错误。

交付快照位置：`backend/.runtime/execution/files.sqlite3`。文件不能绕过账户接口对外公开访问。

## 9. 外观改进的在途工作

本轮已检查旧 Excel 的实际渲染画面，读取前端偏好证据，并核对了相关文档、表格规范。方向是：保留现有深色工作台品牌；文件采用白纸、黑色标题、克制的海军蓝、清晰层级与充足留白。

已新增 `backend/infrastructure/execution/image/zhouxu_office.py` 模板源码，统一生成证据时间线与补证清单；镜像预装该能力，证据整理 Skill 将其作为 Office 交付的优先模板，本轮真实模型文件已完成 LibreOffice 逐页渲染检查。

执行镜像 Dockerfile 已加入 LibreOffice、中文字体和渲染依赖。当前复验使用 Docker Linux 引擎和镜像 `0.2`；本机服务若无法连接 Docker，任务会明确失败，不回退宿主执行。

文件预览界面、预览接口和快照渲染链路已实现：Office 文件进入隔离镜像后由 LibreOffice 转 PDF，再由 `pdftoppm` 生成分页 JPEG，服务端组装自包含 HTML 返回给当前账户的浏览器 Blob；宿主机不直接打开用户文件。

### 外观阶段的完成标准

1. Excel 内容完整，原事实、状态与来源保留；表头、日期、长文本清楚，筛选、冻结和打印可用。
2. Word 实际渲染后逐页检查，无超宽、裁切、孤立标题、不合理空白或表格断裂。
3. 前端能够查看与下载文件对应的真实排版，在桌面和手机上完成核心操作。
4. 后续新任务能够复用样式，而非只手工美化一份演示文件。
5. 相关功能、权限、回归及视觉检查完成后，再提交用户评价；机械检查不能代替用户的认可。
