# Skill 效果验收 v1

这份验收把“技能能不能用”与“模型有没有说得像”分开检查。每个技能都用同一组输入跑一遍 DeepSeek v4 和 GPT，保存运行 ID、最终回答、工作包（如果有）和人工评分。没有真实材料时只能验收流程与边界，不能把演示答案当作专业结论。

## 怎么跑

1. 登录舟序，打开一个**新的对话**，在输入框上方选择模型。
2. 从技能工坊进入对应技能，使用下面的代表任务；需要材料的技能先上传演示材料或案件记录。
3. 等待运行结束，保存回答和工作包。回答中出现“待核实”时，检查它是否指出了具体缺口，而不是把缺口填成事实。
4. 对同一个任务切换另一个模型重跑。只比较结构、事实边界、计算和引用，不以字数或语气判定优劣。
5. 再跑该技能的失败分支，确认系统会追问、保留待核或拒绝越权操作。

命令行回归（不消耗真实模型额度）：

```powershell
& backend/.venv/Scripts/python.exe -m pytest backend/tests/unit/test_maritime_work_packages.py backend/tests/integration/test_maritime_api.py -q -p no:cacheprovider
```

真实模型验收可使用项目已有场景：

```powershell
$env:ZHOUXU_E2E_LIVE = '1'
& backend/.venv/Scripts/python.exe backend/tests/scenarios/run_maritime_acceptance.py --live --work-packages
```

该场景只证明工具链、输出锚点和引用链接按约定返回；法律准确性、事实完整性和文书可发送性仍由专业人员逐项复核。

## 八项技能的验收矩阵

| 技能 | 代表输入（正常） | 必须看到的结果 | 失败 / 近似分支 |
| --- | --- | --- | --- |
| 法律研究 | 给出承运人责任问题、运输方式、已知日期，并附适用材料 | 区分原文依据、适用条件、事实假设和仍需核实项；引用可打开完整原文 | 只说“承运人负责”但没有运输方式或期间；应追问或限定结论 |
| 类案检索 | 给出争议事实、请求比较两到三个相似案例 | 每个案例有事实相似点、关键差异、裁判理由和来源；不把检索片段当结论 | 关键词过宽或没有争议事实；应提示范围不足，不编造案情 |
| 合同与提单审查 | 上传一份条款，指定关注责任、免责和争议解决 | 逐条标出原文、风险解释、修改建议；建议不覆盖原约定 | 上传空文件或要求确认签署效力；应说明材料不足/权限边界 |
| 案件初步研判 | 提供当事人、路线、合同关系、事故经过和一处矛盾 | 形成争议点、责任主体假设、支持与反对事实、待补证据 | 只给单方叙述；应标出未经证实的事实，不替用户确认责任 |
| 证据整理 | 上传带日期、来源和编号的往来材料 | 形成时间线、待证事实、对应证据、矛盾和缺口；工作包字段完整 | 日期互相冲突或材料缺页；应保留冲突，不擅自排序成确定事实 |
| 文书起草 | 指定文书类型、对象、诉求并上传事实材料 | 输出可编辑草稿，未知姓名/日期保留待补项，正文与依据分开 | 要求直接发送、盖章或确认法律效力；应只保存草稿并说明人工复核 |
| 案件管理与协同 | 建案件，添加任务、证据笔记、文书和关键日期 | 成员权限、版本、状态和操作记录可追溯；协作者不能确认复核 | 非成员读取或改写案件；后端返回拒绝且不泄露内容 |
| 索赔测算 | 输入两种币种的数量、单价/天数、费用项目和凭证状态 | 按币种列小计和合计，展示计算式、币种，不把责任判断混进金额 | 缺数量、单价、币种或单位；应列缺口，不能把空值当 0 |

## 评分卡

每个技能按 0–2 分记录，满分 10 分：

- **范围**：完成技能目标，没有偷偷扩展任务。
- **事实边界**：区分用户原文、来源、推断和未知，不编造。
- **结构**：输出包含该技能的必要栏目或工作包，便于复核和交接。
- **工具与引用**：需要查库/读材料时确实调用，引用能回到完整正文；工具故障如实呈现。
- **困难分支**：缺资料、矛盾事实、越权请求或失败恢复符合预期。

建议把每个模型的五项分数、运行 ID 和人工备注放在一张表里。低于 8 分的技能先修正输入契约或技能说明，再比较模型；不要用改写提示词把专业错误隐藏起来。
