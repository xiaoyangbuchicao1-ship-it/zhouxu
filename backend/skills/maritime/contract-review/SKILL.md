# 合同与提单审查

交付一份可带进谈判的条款修改单。

## 需要什么
- 合同、提单或保险条款原文
- 你代表哪一方、最担心的风险、不可退让条件

## 工作路径

### 1. 锁定审查立场

识别托运人、承运人、承租人或被保险人等立场；未给立场时先列双边影响，不擅自代入某方。只审一条不扩展成整份合同重写。

### 2. 读取实际文字及关联条款

read_material/search_material 找条款及定义、优先顺序、附件、适用法和争议解决。OCR断句或缺页保留疑点，不补写成原文。

### 3. 把风险改成可谈的文字

每个问题连接到原文位置、风险触发条件和业务后果。分别给理想修改与可接受底线；不得把没核实的法条当成条款当然无效的依据。

### 4. 先交修改，再交说明

按影响排序输出原文—替代条款并保留改动理由；用 prepare_maritime_work 保存条款修改单。最终保留未决事项，不声称对方已经接受。

## 正式工作包

用户要求完整分析、表格或工作包时，用 prepare_maritime_work 保存下列结构；简短问题直接回答，不为凑格式调用。sections 用 {key,rows} 对象数组；rows 每行按规定列顺序填写字符串数组。缺失信息写“待核”，不填造数据。

- `clauses` 条款修改单：位置、原文、风险、替代条款、谈判底线。

- `questions` 签署前核对：待核事项、为什么影响签署、所需材料。

字段结构示意如下，不是本案事实。sections 每项仅包含 key、rows；每行按上方列顺序填值，不重复写列名。notes放最外层。金额必须来自明确输入，未知数值不能参与运算。

## 交付前检查
- 原文逐字可定位
- 替代条款可以直接编辑而非只有“建议明确”
- 修改考虑交叉定义和双方风险分配

## 分支与回退
- 无原文：请求上传或粘贴条款，只给审查重点，不声称已审查。
- 立场未知：展示双方影响，询问会改变改写方向的一个关键问题。

## 反例

写“责任不清，建议完善”，却没有给出替代文字。
