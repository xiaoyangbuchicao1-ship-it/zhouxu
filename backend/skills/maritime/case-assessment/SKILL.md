# 案件初步研判

形成一份可继续调查的案件判断，而非过早给胜诉结论。

## 需要什么
- 当事人、航线、单证与已知事故经过
- 现有材料和这次需要作出的决定

## 工作路径

### 1. 重建单证和运输关系

区分名义承运人、实际承运人、货主、持单人及代理；用户陈述和文件记载分开，不凭同一公司名称推定同一法律身份。

### 2. 沿时间检查事故链

排列装载、交接、运输、卸载、检验和通知，把损害发现时间与发生时间分开。先定位缺口，不先选一个责任主体再找理由。

### 3. 让相反解释同台比较

至少检验一个与初步主张相反的合理解释。对每种解释列可支持/推翻的证据，不输出无统计基础的胜诉百分比。

### 4. 选择下一项最有价值的调查

给暂定判断、改变判断的关键证据及最多三项优先核实动作；用 prepare_maritime_work 保存关系表和责任假设。

## 正式工作包

用户要求完整分析、表格或工作包时，用 prepare_maritime_work 保存下列结构；简短问题直接回答，不为凑格式调用。sections 用 {key,rows} 对象数组；rows 每行按规定列顺序填写字符串数组。缺失信息写“待核”，不填造数据。

- `relationships` 主体与关系：主体、身份、合同或行为、证据状态。

- `hypotheses` 责任假设对照：争点、支持事实、相反解释、改变判断的证据。

字段结构示意如下，不是本案事实。sections 每项仅包含 key、rows；每行按上方列顺序填值，不重复写列名。notes放最外层。金额必须来自明确输入，未知数值不能参与运算。

## 交付前检查
- 发现损害不等于证明发生环节
- 责任主体有身份与关系依据
- 每个关键未知对应可执行调查动作

## 分支与回退
- 只有一句案情：先交问题地图，不罗列几十项泛化材料清单。
- 出现急迫程序节点：明确核实依据和负责人，不自行算定期限。

## 反例

把货损发现于卸港，直接推成承运人运输途中造成。
