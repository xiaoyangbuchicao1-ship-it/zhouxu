# 索赔辅助

给出能逐笔复算的损失明细，不把数字合计当成可获赔金额。

## 需要什么
- 索赔项目、数量、单价或天数/日费率、币种
- 发票、检验和支出凭证；没有依据的条件应保留未知

## 工作路径

### 1. 先定口径，排除重复项目

区分货值损失、检验费、救助/减损支出等项目，标明数量和费率来自何处。同一损失不能因出现在两张单据中就加两次。

### 2. 核对单位与币种

数量、重量、天数和费率单位一致；跨币种分别列示。滞期等时间计费缺少起止、例外和计时规则时不自行补天数。

### 3. 交给确定性计算

使用 calculate_maritime_claim。保留输入和实际回执，逐项四舍五入至两位；不让模型口算替代工具，不擅自添加责任比例、免赔、利息或汇率。

### 4. 交数字，也交未定条件

用 prepare_maritime_work 保存明细与条件。工作包会重新复算金额；解释哪些数字已算清、哪些条件还影响应赔范围。

## 正式工作包

用户要求完整分析、表格或工作包时，用 prepare_maritime_work 保存下列结构；简短问题直接回答，不为凑格式调用。sections 用 {key,rows} 对象数组；rows 每行按规定列顺序填写字符串数组。缺失信息写“待核”，不填造数据。

- `amounts` 可复算明细：项目、数量、单价、币种、金额。

- `uncertainties` 条件与依据：条件、当前值、缺失依据、影响。

字段结构示意如下，不是本案事实。sections 每项仅包含 key、rows；每行按上方列顺序填值，不重复写列名。notes放最外层。金额必须来自明确输入，未知数值不能参与运算。

```json
{
  "skill_id": "claim-calculation",
  "title": "本次工作标题",
  "sections": [
    {
      "key": "amounts",
      "rows": [
        [
          "待核",
          "待核",
          "待核",
          "待核",
          "待核"
        ]
      ]
    },
    {
      "key": "uncertainties",
      "rows": [
        [
          "待核",
          "待核",
          "待核",
          "待核"
        ]
      ]
    }
  ],
  "notes": []
}
```

## 交付前检查
- 每项金额与数量×单价一致
- 不同币种未合并
- 重复、残值和未核条件被单列

## 分支与回退
- 缺少数值：列已知口径与所缺输入，不用0代替未知。
- 要求利息/时效/责任扣减：先查适用依据与参数，再决定是否能另行计算。

## 反例

把美元货值和人民币检验费直接相加，再说这就是应获赔金额。
