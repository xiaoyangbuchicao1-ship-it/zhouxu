# 法律检索与问答

把一个法律疑问，变成可以核对的规则适用表。

## 需要什么
- 具体争点或拟作的决定
- 事件时间、航线和可能适用法；未知可先留空

## 工作路径

### 1. 界定这次要回答的决定

把“承运人负责吗”拆成责任期间、损害原因、抗辩或限制等真正影响决定的争点。日期/法域未知时先研究一般规则，不冒充适用意见。

### 2. 沿版本找到规则和例外

调用 search_maritime_corpus(laws)，按事件日期核对现行/历史版本。检索不仅找支持规则，也找例外、但书和相反条件。无时间信息不默认最新版当然适用。

### 3. 把规则落回事实

逐项说明适用前提满足、未满足或未知。未知项写明需要哪份凭证，指出哪一项新事实会翻转结论。一般资料研究不强迫用户先补齐整宗案件。

### 4. 形成适用表

先给直接回答，再交规则适用表及事实对应表。正式研究工作包调用 prepare_maritime_work；引用用工具返回的短标记。

## 正式工作包

用户要求完整分析、表格或工作包时，用 prepare_maritime_work 保存下列结构；简短问题直接回答，不为凑格式调用。sections 用 {key,rows} 对象数组；rows 每行按规定列顺序填写字符串数组。缺失信息写“待核”，不填造数据。

- `rules` 规则适用表：争点、规则、适用条件、时间版本、依据。

- `application` 事实与规则对应：已知事实、规则对应、待核条件。

字段结构示意如下，不是本案事实。sections 每项仅包含 key、rows；每行按上方列顺序填值，不重复写列名。notes放最外层。金额必须来自明确输入，未知数值不能参与运算。

{
  "skill_id": "law-research",
  "title": "本次工作标题",
  "sections": [
    {
      "key": "rules",

        [
          "待核",

## 交付前检查
- 每条确定性规则有实际检索依据
- 版本日期与事件日期没有混用
- 没有把“未检索到”当作“不存在规则”

## 分支与回退
- 只问术语或常识：直接解释，不强制输出完整表格。
- 找不到可靠原文：交检索线索和缺口，不编造条文或时效。

## 反例

只堆三条法条，却不说明哪一条适用于什么事实。
