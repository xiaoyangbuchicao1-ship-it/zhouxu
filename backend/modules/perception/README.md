# 感知模块

2026-11-02：生产入口为 `TextPerception(settings, model_context)`。模型端口必须提供当前模型的能力预算与完整请求编码估算；不再使用条目字符预算或 `packing.py`。后者已确认没有生产或测试引用后移除。

`normalize.py` 先按记录身份去重并验证执行关系，保留不同来源；外部材料和网页保持 user 数据身份。部分材料仍保留实际已解析正文，不清空 partial 内容。最新要求、纠正、任务状态以及本轮最近工具调用和其全部结果受到保护；历史来源引用不等于已读取证据。

本轮资源紧邻当前用户请求，位于本轮执行历史之前，避免开头预览出现在后续正文回执之后。记录内的工具调用与全部结果顺序保持不变；不通过调整消息顺序改变来源身份或权限。材料完整可读与其中陈述是否正确仍是两项不同判断。

材料读取端分开使用正文长度、Harness分配额度及已预留的封装预算，不因封装略超正文长度就反复减半。用于确定返回大小的试读不写阅读状态；选定回执后才提交该回执的实际覆盖范围。工具结果可用与正文已进入模型仍由不同阶段记录。

`selection.py` 在完整请求不超过W时使用已选表达，不填满T。材料初始是共享小预览和入口，正文由独立搜索/读取工具按需提供。超过W后先缩减可续读的材料表达；普通结果累积仍有压力时交给Harness语义整理，摘要与覆盖ID提交后才省略旧交互，不在感知静默删除。只有单个结果自身过大才先外置为可读入口。工具调用和结果保持完整关联，最新回执不得因不在旧摘要里被误判为缺失。

唯一预算算法在 `infrastructure/model/budget.py`，感知通过 `ModelContextPort` 使用它；系统提示、当前工具、当前输入、必要历史、记忆、材料、RAG、反馈、协议和多模态均在适配器编码后计数。发送前传输层再次检查。字符数只用于解析或读取资源限制，不再冒充模型窗口。

`assembly` 记录当前预算、估算 token、选中/降级/省略原因和整理前后压力。Trace 不复制材料正文，公开 API 不投影内部 diagnostics。内部身份的公开文本映射独立保留，不进入供应商请求；流式与最终答案共用后端公开投影。

当前采用保守UTF-8字节估算和独立图像上界，并非精确tokenizer。模型能力未知时只使用明确标记的保守配置；职责与限制以 `docs/architecture.md` 第14节和材料导航评估为准。读取覆盖、任务完成和答案正确性分别核验。

2026-11-04：inventory.py为每次实际选中的items重建context_inventory。相同解析版本、确有正文支撑的coverage才累计可见长度；重叠区间取并集。读过的账本、摘要、裸引用均不能代替本次原文。索引列出当前目标位置、材料解析状态/正文可见量/缺口/视觉内容、近期操作，以及已提交阶段交付和剩余工作，不推断题号或任务完成。

选择阶段的每次measure和最终组装使用相同索引生成逻辑；压力裁减正文后，索引也随之重算，防止陈旧的“全文可见”误导模型。索引属于Harness生成的数据说明；系统指令只来自配置。最新补充与续做状态在模型编码时位于索引之后。索引没有额外调用模型，也没有强制多出规划轮次。

2026-11-04用户选定查库候选：保持原可见覆盖算法，在近期观察中关联查询和人可读来源标签，并将当前目标及原文入口放在索引末尾。没有把工具报告的missing_aspects升级为任务待办，也不从检索完成推断业务判断完成。索引及新增元信息仍进入原预算；不增加规划模型调用。
