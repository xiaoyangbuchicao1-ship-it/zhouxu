# 记忆模块

2026-11-02 预算交接：Harness 通过 `unified_budget=True` 使用现有召回顺序和完整交换分组，把候选正文交给感知统一预算，不在召回阶段按字符数或项目数裁掉已取得的必要记录。近期背景候选窗口仍是本模块资源边界，当前 Run、明确引用、保护项和工具配对仍按既有规则取得。独立记忆调用继续可用自己的资源限制；它不是任何模型的上下文容量。未改分层保留、任务进度或召回排序算法。历史证据引用的模型投影不含内部 chunk 身份，也不构成本轮已读取正文。

记忆模块保存和召回三类状态：不可变的 `MemoryRecord`、可更新的 `TaskState`，以及按预算生成的 `MemoryRecall`。

第一版使用内存仓储适配器，仓储端口位于 `backend/contracts/ports.py`。正式数据库尚未选型，替换数据库时不改变模块契约和召回策略。

## 生命周期

应用层提供 `session_id`，Harness 为每次消息生成新的 `run_id`。一次运行中的用户输入、模型决定、工具结果和反思反馈都写入当前 session，并带有当前 run。关闭运行仅删除该 run 中 `retention=run` 的记录；`session/task` 记录和任务状态保留。显式 `purge_session` 清理该会话全部记录、索引和任务状态，不影响其他会话。

缺少 `session_id` 的旧调用使用临时 session 以保持首条链路兼容；正式用户会话不能依赖该兼容行为。

## 召回

召回分为“取候选”和“按预算选完整单元”，不能先截断所有候选再找重要信息：

1. 通过索引分别取得近期背景、当前 run、明确引用和有效的纠正/约束/未解决项。任务专属保护项只对同一 task 生效；同一 session 的其他任务历史仍可能作为背景，需要严格任务隔离时须另定边界。
2. 从工具 `action_id` 找齐同一 session/run 内的调用与全部结果，候选窗口切到结果时也补齐整组；不全量复制历史正文。
3. 保护任务状态、当前用户输入、有效保护项、明确引用及当前 run 中未完成的工具依赖。已完成的工具交换和历史背景按最近完整单元作为可省略候选。
4. `max_items/max_chars` 同时适用于完整单元。明确引用缺失或当前工具交换未完成时，`recall` 返回 `needs_input`；普通内容超预算会记录省略原因并继续，不把内部预算压力伪装成用户缺少信息。当前请求本身无法装入时，感知返回内部失败，等待逻辑不会被触发。
5. 无关旧工具交换不完整时整组省略，记录 `incomplete_tool_exchange`，正常新请求继续。历史放在当前请求之前，当前运行的工具反馈跟在当前请求之后。

输出 `records` 是感知使用的权威数据，`items` 只兼容旧的 `summary/updates` 读取方式，两者不能重复注入模型。`MemoryInput.items` 是有类型的 `MemoryRecord` 列表，兼容旧 `FeedbackRecord` 对象及字典；JSON 往返保留正文、分类、关联、状态、保留范围与时间。

记录写入前核对 session/run/task，任何显式归属冲突均拒绝整批。编号相同且内容相同可幂等重传；内容冲突则整批不写并返回 `failed`。`record` 的成功只表示写入成功，附带召回视图若暂不可用，通过 `blocked_reason` 说明；下一次 `recall` 才据此停止。这样分次写入工具请求和结果不会在中间步骤被错误阻断。

任务状态以 `(session_id, task_id)` 保存。已有版本必须匹配 `expected_revision`；省略时使用提交的 `state.revision` 作预期版本。仓储产生下一版本，调用方不能跳号。目标、步骤和阻塞项会成为感知保护项；当前没有从对话自动提取任务计划的功能。

`trace` 记录候选 ID、保护/选择原因、窗口外条数、任务版本与耗时；`omitted_reasons` 记录已评估但省略的条目。窗口外的普通背景仅报告数量，不声称逐条评估过。Trace 不复制正文，统计不可用不阻断召回。

参数预算沿用 `config/defaults.toml`；窗口倍数是 `service.py` 的可注入默认常量，保护类型是 `recall.py` 的策略默认常量。第一版不使用向量记忆库、自动语义摘要、长期用户画像或失败日记。可替换策略和仓储实现；新增查询能力时仍应显式演进端口，不承诺所有未来能力都无需改契约。

## 边界

记忆不负责账户认证、权限判定和法规检索。动态 RAG 尚未桥接主循环；未来应只把查询、chunk、文献和版本引用写入长期记忆，不把检索分数当作法律结论置信度。当前仅为单进程内存仓储；重启不保留数据，也不提供生产多租户认证。

回归与性能证据见 `docs/evaluations/memory-handoff-20261031.md`。
