# 推理模块

负责基于上下文、记忆和证据提出假设、计划和下一步行动。

推理不直接执行工具，也不直接修改业务数据库。

## 当前基线（2026-11-03）

仍只有 answer / action / needs_input 三种决策，不增加固定的意图识别、规划或评审调用。
简单办公任务直接交付；需要资料时提出本轮工具请求。action_id 在同一批内必须唯一，
避免错误决定导致重复执行；已有完整性与运行归属检查继续保留。

主提示词按 system / task / evidence / delivery 四部分外置在 defaults.toml，模型适配器
依次组装。工具说明、运行中的重复反馈、上下文整理与收尾提示分别维护，不加载 Skill。
工具的正常、部分、无结果、错误回执都属于下一轮观察，不能被当成任务已经完成。

完成依据目前是模型指令与结构检查，尚非独立的语义评审。真实测试仍发现过度检索、
作答范围漂移、追问未进入等待状态。不能声称本轮已解决专业正确性或所有完成判断。
结果与边界见[推理行动评估](../../../docs/evaluations/reasoning-action-20261103.md)。

## 当前补充：明确决定与恢复输入

speed预设的主模型使用原生控制操作明确交付或等待，适配器转换为原三种DecisionProposal，
不新增规划/评审调用，也不把交付注册到Action。正文从交付参数安全投影为普通流式文本；
截断不标完成，单条问题字符串可有限转换为列表，未知形状不猜测。
最新用户补充由适配器作为独立用户消息放在旧观察之后，避免旧的“缺资料”决定掩盖补充。
普通语义正确性仍依赖模型与证据，专业题尚未稳定；不能以明确交付等同内容正确。
实测与撤回的提示词候选见[本轮报告](../../../docs/evaluations/reasoning-action-opt-20261103.md)。

2026-11-04更新：生产主模型统一DeepSeek的none/low/high，替代上述speed等组合。主模型依旧自行选择交付/行动/补充。explicit控制配合auto工具选择；完整最终正文也可交付，阶段成果、系统受阻和等待保持显式控制。context_inventory说明本次可见材料与近期回执，模型对照目标决定缺什么，不把读取完成当作任务完成。语义判断仍由模型承担，并未新增独立语义裁判。

供应商思考续接由模型适配器和ModelContinuationPort管理；模块不读取隐藏思维链，也不持有供应商字段。思考内容按Run关联工具/决定，仅在私有检查点保存并参与预算；公开Trace只留公开动作、耗时和用量。收尾不固定在第六轮，50为配置上限。更多思考/更多轮次都不能替代证据和答案质量评估。
